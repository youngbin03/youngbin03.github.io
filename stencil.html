안녕하세요!

미리캔버스 AI 팀 인턴 지원을 준비하며 혼자 만든 프로젝트, Stencil을 소개하려고 해요.

출발 질문은 하나였어요. "좋은 템플릿의 감각을, 코드가 재사용할 수 있는 규칙으로 바꿀 수 있을까?" 결론부터 말하면 AI에게 자유를 줄수록 결과가 나빠졌어요.

문제는 생성 능력이 아니었어요

지원을 준비하며 AI 프레젠테이션 서비스를 전부 써봤어요. 낱장은 그럭저럭인데 열 장을 이어 붙이면 같은 문서로 보이지 않았어요. 요소가 겹치고 어긋나고, 품질도 매번 달랐고요.

처음엔 모델 성능 문제로 봤는데, 뜯어볼수록 다른 결론에 닿았어요.

문제는 AI의 생성 능력이 아니라,
생성할 수 있는 디자인의 범위가 정의되지 않은 것 아닐까?

원칙을 한 문장으로 못 박았어요. "AI는 의미를 판단하고, 위치·크기 계산은 코드가 책임진다."

규칙을 굽고, 규칙으로 찍었어요

파이프라인은 두 단계로 나눴어요. 테마당 한 번 도는 BAKE와, 요청마다 도는 STAMP예요.

1) BAKE — 템플릿 분석

템플릿을 한 번 분석해 색 팔레트 · 글자 크기 체계 · 격자 · 레이아웃 골격을 하나의 규칙 묶음으로 정리해요. 원본을 복사·붙여넣기 하지 않고, 이후에는 추출한 규칙만 재사용합니다.

2) STAMP — 슬라이드 생성

요청이 오면 그 규칙만으로 좌표를 새로 계산해요. AI는 "KPI 3개니까 3열 카드"처럼 레이아웃 의미만 고르고, 실제 위치·크기·정렬은 코드가 격자와 실측값으로 계산합니다. AI가 좌표·색·크기를 직접 결정하지 못하도록 출력 구조 자체를 제한했어요.

3) 품질 자동 채점

만든 슬라이드를 7개 지표로 자동 채점하고, 동시에 원본 템플릿과 얼마나 다른지도 점수로 매겨요. 지나치게 유사하거나 기준에 미달한 결과는 자동으로 수정하거나 폐기합니다.

자유도를 줄여서 품질을 얻었어요

가장 크게 망가진 건 배경 장식이었어요. 화면을 채워야 자연스러운 장식을 작게 줄여 모서리에 처박거나, 구석용 작은 장식을 화면 절반만 하게 키웠죠. 큰 장식을 가져와 구석 장식의 문법으로 배치한 거예요.

배치 규칙을 아무리 정교하게 써도 같은 실패가 반복됐어요. 장식은 에셋 자체보다 원래 쓰인 크기와 위치의 관계가 중요했거든요.

결국 자유로운 변형을 포기했어요. 원본의 크기·위치는 고정하고 AI는 조합을 고르거나 색만 바꾸게 했습니다. 생성 자유도는 줄었지만 실패 가능성과 품질 편차가 크게 낮아졌어요.

잘 만드는 것보다, 망가지지 않게

품질 하한은 코드가 강제하게 했어요.

  1. 안전 여백 ≥ 5%
  2. 최소 글자 크기 약 18px
  3. 핵심 글자 크기 약 54px
  4. 요소 간 겹침 0

이 값들은 처음부터 정한 게 아니라 실패를 보고 거꾸로 다듬은 것이에요. 안 읽히는 글씨를 보고 최소 크기를 12px에서 18px로 올렸고, 목업 안의 빈 화면을 못 찾던 문제는 이름표 없는 도형을 상위 그룹으로 되짚게 고쳐 인식률을 0개에서 5개로 끌어올렸습니다.

AI 평가는 아직 못 믿었어요

렌더링된 슬라이드를 AI가 채점하게 하는 것도 실험했어요. 그런데 사람이 보기엔 완성도가 낮은 결과를 AI가 높게 평가하는 경우가 반복됐어요.

겹침·정렬·여백처럼 명확한 오류는 규칙으로 잡히지만, 템플릿 특유의 분위기와 완성도는 점수 하나로 판별되지 않았어요. 좋은 결과를 생성하는 문제와 판별하는 문제는 서로 다른 난제예요.

모델 성능을 올리기 전에 실패 조건을 먼저 정의하고, 결정론적 규칙과 AI 평가의 담당 영역을 나눠야 한다는 결론을 얻었습니다.

그래서 남은 문장은 이거예요. AI 디자인 제품의 품질은 생성 자유도가 아니라, 무엇을 고정하고 무엇만 변화시킬지 결정하는 시스템 설계에서 나온다.

여기서 못 푼 배경 장식 문제는, 인턴 합류 후 다음 프로젝트에서 다시 다루게 됩니다.
